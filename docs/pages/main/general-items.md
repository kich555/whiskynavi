# 일반상품 판매 — `/general-items/*`

사용자 화면. 일반상품(위스키 병이 아닌 배송 주문 가능 상품) 판매 공고 열람, 장바구니, 배송 주문, 토스 결제까지의 전체 구매 흐름. 비회원 주문을 허용하며 장바구니 토큰 쿠키로 신원을 유지한다.

## 라우트 맵

| 경로 | 유형 | 비고 |
|---|---|---|
| `/general-items` | 판매 공고 카드 목록 | OPEN 상태 일반상품만 |
| `/general-items/[saleId]` | 공고 상세 + 주문 폼 | ★ 이 화면군 진입점 |
| `/general-items/cart` | 장바구니 + 견적 | 비회원 장바구니 토큰 기반 |
| `/general-items/cart/order` | 배송 주문서 + 토스 결제 | ★ 이 화면군 핵심 |
| `/general-items/cart/order/toss/success` | 토스 결제 성공 콜백 | 자동 승인 확정 |
| `/general-items/cart/order/toss/fail` | 토스 결제 실패 콜백 | |
| `/general-items/delivery-order` | 강제 리다이렉트 | `/cart/order`로 이동 — 레거시 호환 |
| `/general-items/delivery-order/toss/success` | 강제 리다이렉트 | `/cart/order/toss/success`로 이동 — 레거시 호환 |
| `/general-items/delivery-order/toss/fail` | 강제 리다이렉트 | `/cart/order/toss/fail`로 이동 — 레거시 호환 |

## 공용 개념

### 장바구니 신원 (카트 토큰)

비회원도 장바구니를 쓸 수 있어야 한다. 인증 토큰이 있으면 `Authorization` 헤더로, 없으면 `X-Cart-Token` 쿠키(`wn_cart_token`)로 장바구니 신원을 식별한다. 둘 다 없으면 빈 장바구니로 취급.

- **토큰 영속화**: API 응답에서 카트 토큰을 추출해 httpOnly 쿠키로 저장. 이후 모든 장바구니 API 호출에 첨부
- **회원/비회원 전환**: 회원이 쿠키 없이 진입하면 `getOrCreate`로 장바구니를 생성 후 토큰을 쿠키에 저장
- **장바구니 없음(400) 처리**: 토큰이 무효화된 경우 빈 장바구니로 정상 응답 — 에러로 노출하지 않음. 단, 상품 추가 시엔 쿠키를 클리어하고 재시도

### 주문 완료 마커 (`wn_cart_completed`)

결제 확정 성공 직후 카트 토큰 쿠키를 삭제하고 완료 마커 쿠키를 설정한다. 이 마커가 있으면 회원이 다시 장바구니로 돌아가도 이전 주문의 장바구니를 복원하지 않는다 — 중복 주문 방지.

### 결제 멱등성

주문서 페이지에서 결제 시도마다 멱등키(UUID, 폴백 `Date.now()-random`)를 발급한다. 같은 시도 내에서 티켓 생성에 실패하면 키를 클리어하고 다음 시도에서 새 키를 발급. 멱등키는 `Idempotency-Key` 헤더로 전송되어 중복 결제를 서버 단에서 차단한다.

### 수량 한도

상세 페이지의 주문 수량 한도는 `min(잔여수량, 최대주문수량)`. 최대주문수량이 없으면 잔여수량이 한도. 장바구니에서는 행별로 `min(잔여수량, 최대주문수량)`을 상한으로 클램프.

### 결제 흐름 (토스)

1. 주문서 폼 제출 → 토스 결제 티켓 생성(서버 액션) — 멱등키 포함
2. 티켓의 `successUrl`/`failUrl`로 토스 SDK 결제창 호출 (클라이언트)
3. 토스가 success/fail URL로 리다이렉트 (query: `orderId`, `paymentKey`, `amount`)
4. 성공 페이지에서 결제 확정 서버 액션 자동 호출 → 주문 완료 패널

## 페이지별 맥락

### /general-items — 판매 공고 목록

판매중(OPEN) 상태의 일반상품 공고를 카드 그리드로 노출. `saleType=GENERAL`, `productType=ITEM`, `saleStatus=OPEN` 필터로 판매 공고 API 조회.

**카드 내용**:

| 상품명 | 상태 | 가격 | 잔여수량 | 액션 |
|--------|------|------|----------|------|
| 글렌피딕 18 | 판매중 | ₩180,000 | 35 / 50개 | 상세보기 |
| 맥콜 12 | 품절 | ₩95,000 | 0 / 50개 | 주문 불가 |

- **품절 카드**: 잔여수량 0이면 "주문 불가" 비활성 버튼 — 상세로 이동하지 않음
- **비회원 주문 조회 링크**: 우측 상단 → `/orders/guest`
- **페이지네이션**: URL 기반(`page`, `limit`), 공유 가능

### /general-items/[saleId] — 공고 상세 + 주문 폼 ★

판매 공고 1건의 상세 정보와 주문 폼. 이 화면군의 진입점.

**강제 리다이렉트/비활성화 조건**:
- 공고가 OPEN 상태가 아니면 `notFound()` — 닫힌 공고는 접근 불가
- 품절(잔여수량 0)이면 주문 폼 대신 "주문 불가" 비활성 표시

**뷰 구성**:
- 상품 이미지 + 상품명 + 판매상태 배지(판매중/품절)
- 가격, 잔여/총 수량
- 주문 폼: 수량 선택(1 ~ 수량한도) + "장바구니 담기" / "바로 주문" 버튼
- 상품 설명
- 판매정책 섹션: 배송업체(CJ대한통운), 배송비(₩3,000), 배송기간(2~5영업일), 교환·반품 조건

**주문 폼 액션** (폼 제출 시 `intent` 필드로 분기):
- `addToCart`: 장바구니에 상품 추가 → 성공 메시지 + "장바구니 보기" 링크 노출
- `orderNow`: 장바구니에 상품 추가 후 `redirect('/general-items/cart/order')` — 장바구니를 거치지 않고 바로 주문서로 이동

**"목록으로 돌아가기" 버튼**: 상단. `<Link href="/general-items">` — `router.back()`이 아닌 고정 경로 push. 직접 진입해도 안전.

### /general-items/cart — 장바구니

RSC에서 견적(quote)을 페칭해 클라이언트 컴포넌트에 전달. 장바구니 신원이 없으면 빈 견적.

**장바구니 항목 테이블**:

| 상품명 | 설명 | 수량 | 행 금액 | 액션 |
|--------|------|------|---------|------|
| 글렌피딕 18 | 판매 공고 12 | 2 | ₩360,000 | [-][+][삭제] |
| 맥콜 12 (주문 불가) | 판매 공고 11 | 1 | ₩95,000 | 비활성 |

- **주문 불가 항목**: `valid === false`이면 "주문 불가" 배지 + 사유 표시, 수량 변경/삭제 비활성화
- **수량 변경**: 서버 액션 → `revalidatePath`로 장바구니/주문서 캐시 갱신. 행별 상한(잔여수량, 최대주문수량)으로 클램프
- **삭제**: 서버 액션 → 캐시 갱신
- **주문 요약**: 상품 금액 / 배송비 / 총 결제 금액 + 무료배송까지 남은 금액 안내

**체크아웃 가능 여부** (`canCheckoutCart`):
- 유효한(valid) 항목이 1개 이상 있어야 "주문서로 이동" 버튼 활성화
- 모든 항목이 무효하면 블로킹 사유("주문 가능한 상품이 없습니다.") 표시, 버튼 비활성화
- 빈 장바구니면 버튼 자체 미노출

**"뒤로가기" 버튼**: `router.back()` — 공용 패턴. 직접 진입 시 이전 페이지가 없을 수 있음.

### /general-items/cart/order — 배송 주문서 + 토스 결제 ★

이 화면군의 핵심. RSC에서 견적 + 회원정보 + 배송지 목록을 병렬 페칭(`Promise.allSettled`)해 클라이언트 컴포넌트에 전달.

**강제 리다이렉트/빈 상태 처리**:
- 유효한 장바구니 항목이 없으면 빈 상태 안내 + "장바구니로 이동" 링크

**폼 필드**:
- 수령인 이름 / 연락처 (필수)
- 주문 안내 이메일 (필수, 비회원 주문 조회 코드 발송용)
- 배송 주소: 카카오 우편번호 검색 → 우편번호/기본주소(읽기전용) + 상세주소 입력
- 배송 메모 / 주문 메모 (선택)

**회원 전용 기능** (인증 토큰 있을 때만):
- "주문자와 같음" 체크박스: 회원 이름/연락처/이메일 자동 입력 + 기본 배송지 적용. 기본 배송지가 없으면 배송지 추가 다이얼로그 자동 오픈
- 배송지 주소록 드롭다운: 저장된 배송지 선택 → 폼 자동 채움. 기본 배송지는 `[기본]` 표시
- 배송지 추가 다이얼로그: 새 배송지 저장 → 주소록에 추가 + 폼에 적용. 기본 배송지로 설정 시 기존 기본 배송지 해제

**결제 버튼** ("결제"):
1. 폼 입력으로 주문 입력 구성 (배송주소는 우편번호+기본주소+상세주소를 단일 문자열로 결합)
2. 멱등키 발급 (시도별 1회, 실패 시 클리어)
3. 토스 결제 티켓 생성 서버 액션 호출
4. 티켓의 `clientKey`/`pgOrderId`/`amount`/`successUrl`/`failUrl`로 토스 SDK 결제창 호출
5. 토스가 success/fail URL로 리다이렉트

**주문 요약 사이드바**: 유효 항목 목록 + 상품 합계 / 배송비 / 총 결제 금액. "최종 금액은 서버 검증 결과 기준" 안내 포함.

**에러 메시지 가이드**: 서버 에러를 사용자 친화적으로 변환:
- 주문 티켓 만료 → "결제 가능 시간이 만료되었습니다. 주문을 다시 시도해 주세요."
- 권한 부족 → "이 상품을 주문할 권한이 없습니다. 로그인 계정 또는 회원 등급을 확인해 주세요."
- 수량 부족 → "남은 수량이 부족합니다. 장바구니 수량을 다시 확인해 주세요."

**"뒤로가기" 버튼**: `router.back()`. "취소" 버튼은 `<Link href="/general-items/cart">` 고정 경로.

### /general-items/cart/order/toss/success — 토스 결제 성공 콜백 ★

토스 결제 완료 후 리다이렉트되는 페이지. query(`orderId`, `paymentKey`, `amount`)를 받아 **결제 승인을 확정**하는 콜백 라우트.

**자동 확정 로직** (핵심):
- 페이지 로드 시 `useRef` 플래그로 **1회만** 자동 결제 확정 서버 액션 호출 — Strict Mode/리렌더 중복 호출 방지
- 진행 중: "결제를 확정하는 중입니다." 상태 표시
- 성공: 주문 완료 패널 노출
- 실패: 에러 메시지 + "같은 결제 정보로 다시 확정" 버튼(수동 재시도) + "주문서로 돌아가기" 링크

**결제 확정 서버 액션** (`confirmGeneralItemCartTossPayment`):
- `orderId`/`paymentKey`/`amount` Zod 검증 (amount는 숫자로 coerce)
- 토스 결제 확정 API 호출
- 성공 시: 카트 토큰 쿠키 삭제 + 완료 마커 쿠키 설정 + 캐시 갱신 — 장바구니 초기화
- 쿠키/캐시 정리 실패가 성공 응답을 덮지 않도록 안전장치

**주문 완료 패널** (공용 컴포넌트, delivery-order에서도 사용):
- 주문번호, 주문상태, 결제수단/상태/금액/일시
- **비회원 조회 코드**: `guestOrderToken`이 있으면 강조 표시 + 클립보드 복사 버튼. "조회 코드는 최초 주문 완료 화면에서만 다시 확인할 수 있습니다" 안내 — 재확인 불가하므로 보관 권장
- 이동 버튼: 비회원이면 "비회원 주문 조회"(`/orders/guest?...`), 회원이면 "내 주문 보러가기"(`/my-page?tab=orders`) + "홈으로"

### /general-items/cart/order/toss/fail — 토스 결제 실패 콜백

토스 결제 실패/취소 시 리다이렉트. query(`code`, `message`, `orderId`)를 그대로 표시.

- 에러 코드 + 메시지 노출 (기본값: "결제가 취소되었거나 인증에 실패했습니다.")
- "주문 다시 시도" → `/general-items/cart/order`
- "장바구니로 돌아가기" → `/general-items/cart`

### /general-items/delivery-order — 강제 리다이렉트 ⚠️ 레거시

`redirect('/general-items/cart/order')` — 즉시 주문서로 이동. 과거 단일 상품 배송 주문 경로의 호환 엔드포인트. 페이지 본문 없음.

### /general-items/delivery-order/toss/success|fail — 강제 리다이렉트 ⚠️ 레거시

각각 `/general-items/cart/order/toss/success|fail`로 query를 보존해 리다이렉트. 과거 토스 콜백 URL 호환.

**주의**: 이 레거시 경로들은 단일 상품 직접 배송 주문에서 장바구니 기반 주문으로 흐름이 통합된 흔적. 실제 결제 확정 로직은 `/cart/order/toss/success`에만 존재하며, 레거시 success는 단순 리다이렉트만 수행한다.

## 상태 전이

### 주문 상태 (서버 기준)
`주문 접수 → 결제완료 → 배송중 → 배송완료`

비회원은 주문 취소가 가능: 주문번호 + 조회 코드로 `/orders/guest`에서 취소.

### 장바구니 항목 유효성
- `valid: true` → 주문 가능
- `valid: false` → 재고 부족/공고 종료 등으로 주문 불가, `invalidReason` 표시

### 결제 확정 상태
- 토스 결제 성공 리다이렉트 → 자동 확정 진행 중
- 확정 성공 → 주문 완료 + 장바구니 초기화
- 확정 실패 → 수동 재시도 가능 (같은 결제 정보로)

## 데이터 흐름 (개요)

- 목록/상세/장바구니/주문서 페이지는 RSC. 인증은 `getAuthToken()`.
- 장바구니 API는 인증 토큰 또는 카트 토큰 쿠키로 신원 식별. 비회원도 장바구니 사용 가능.
- 변경 액션(장바구니 추가/수량변경/삭제, 티켓 생성, 결제 확정, 배송지 저장)은 Server Action → Orval API.
- 장바구니 변경 후 `revalidatePath`로 장바구니/주문서 캐시 갱신.
- 토큰 리프레시/에러 핸들링은 mutator가 일괄 처리.
- 우편번호 검색은 카카오 우편번호 API 스크립트 동적 로드.
- 결제는 토스 페이먼츠 v2 SDK 동적 로드.

## 외부 의존

- **인증**: NextAuth (회원 전용 기능만, 비회원 주문 허용)
- **API**: 원격 백엔드 `api.whiskynavi.com` (Orval 코드젠 클라이언트)
- **결제**: 토스 페이먼츠 v2 — SDK 동적 로드, success/fail 콜백 URL 방식
- **우편번호**: 카카오 우편번호 API
- **배송**: CJ대한통운, 기본 배송비 ₩3,000
