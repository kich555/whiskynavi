# 관리자 보틀 주문 관리 — `/admin/bottle-orders/*`

보틀(위스키 병) 주문 내역을 관리자가 조회. 일반상품 주문(`general-item-orders`)과 같은 주문 테이블을 공유하되, 보틀 주문은 **조회 전용**으로 동작 — 배송 처리·취소·CSV 일괄 발송 액션이 비활성화된다.

## 라우트 맵

| 경로 | 유형 | 비고 |
|---|---|---|
| `/admin/bottle-orders` | 보틀 주문 목록 | 조회 전용 |
| `/admin/bottle-orders/[orderId]` | 주문 상세 | 일반상품 주문 상세와 화면 공유 |

## 도메인 배경: 보틀 주문 vs 일반상품 주문

두 라우트는 동일 주문 API(`getApiAdminOrders`)에서 `productType`으로 분기한다.

| 구분 | 보틀 주문 | 일반상품 주문 |
|---|---|---|
| `productType` | `BOTTLE` (고정) | `ITEM` (고정) |
| 배송방식 | 직배송/픽업 — **사용자 필터 선택** | 직배송 고정 |
| 배송시기 | 바로배송/예약판매 — **사용자 필터 선택** | 바로배송 고정 |
| 관리 액션 | **조회 전용** (상세 버튼만) | 배송 수정·발송·완료·취소·CSV |

보틀 주문은 예약 판매·픽업이 섞일 수 있어 두 축이 필터가 되고, 반면 일반상품은 직배송+바로배송으로 고정이다. 관리 액션은 일반상품 라우트에서만 노출된다.

> 참고: `/admin/orders`는 레거시 진입점으로, 모든 쿼리를 `/admin/general-item-orders`로 **강제 리다이렉트**한다. 보틀 주문 라우트가 아님.

## 공용 컴포넌트 (admin/_components/)

이 화면군은 `/admin/orders/_components/`의 주문 전용 컴포넌트를 general-item-orders와 공유한다. 공용 마킹은 두 라우트 모두에서 쓰임을 의미.

| 컴포넌트 | 역할 | 동작 |
|---|---|---|
| `AdminHeader` (공용) | 상단 헤더(타이틀, 사이드바 토글) | 사이드바 토글은 context. 검색 비활성화(`showSearch={false}`) — 본문 필터 영역 사용 |
| `Pagination` (공용) | URL 기반 페이지네이션 | `router.push(basePath?page=&limit=&...)`. 북마크/공유 가능 |
| `AdminOrdersContent` (주문 공용) | 주문 목록 테이블 + 필터 + 액션 | `enableGeneralItemActions` 플래그로 동작 분기 (아래). basePath로 행 상세 이동 |
| `AdminOrderDetailContent` (주문 공용) | 주문 상세 섹션들 | "주문 목록으로 돌아가기" = `router.back()` |

**`enableGeneralItemActions` 플래그 동작 차이**:

| 동작 | `false` (보틀) | `true` (일반상품) |
|---|---|---|
| 필터: 배송방식/배송시기 | 노출 (사용자 선택) | 숨김 (고정값) |
| CSV 일괄 처리 섹션 | 숨김 | 노출 (검증→실제 처리) |
| 행 액션: 배송수정/발송/완료/취소 | 숨김 | `availableAdminActions` 기반 노출 |
| 행 관리 열 표시 | "조회 전용" 텍스트 | 액션 버튼들 |

## 페이지별 맥락

### /admin/bottle-orders — 보틀 주문 목록

**필터 영역** (URL searchParams 동기화, 페이지 1로 리셋):

- 검색어 (주문번호/고객명/연락처/상품명) — Enter 또는 검색 버튼
- 배송방식: 전체/직배송/픽업
- 배송시기: 전체/바로배송/예약판매
- 주문상태: 전체/결제대기/준비중/배송중/배송완료/취소요청/취소거절/주문취소
- 결제수단: 전체/토스
- 결제상태: 전체/결제완료/결제취소
- 비회원: 전체/비회원만

**주문 테이블** (열 순서):

| 주문 | 고객 | 상품 | 결제 | 주문 구분 | 관리 |
|------|------|------|------|-----------|------|
| BOTTLE-1042 / 2026.07.30 14:32 / 배송중 | 홍길동 / 010-1234 / 회원 | 글렌피딕 18 · 총 2개 / 상품 ₩360,000 / 총 ₩365,000 | 토스 / 결제 완료 | 보틀 / 직배송 / 바로배송 / 보틀 주문 | [상세] 조회 전용 |
| BOTTLE-1043 / 2026.07.30 15:01 / 결제 대기 | 김사장 / 010-5678 / 비회원 | 맥콜 12 (예약) · 총 1개 / ₩95,000 | 토스 / 결제 대기 | 보틀 / 픽업 / 예약판매 / 사업장 55 | [상세] 조회 전용 |

- **주문 열**: 주문번호, 생성일시, 상태 배지(컬러 매핑)
- **고객 열**: 이름, 연락처, 회원/비회원 구분
- **상품 열**: 상품 요약 + 출처 배지(장바구니/단건/관리자수동), 라인 수, 라인별 상품명·수량·금액(최대 2개, 나머지 "외 N개"), 가격 분해(상품합계/배송비/총액/무료배송)
- **결제 열**: 결제수단, 결제상태
- **주문 구분 열** (보틀 모드 전용): 상품유형/배송방식/배송시기 라벨 + 사업장 ID 또는 "보틀 주문"
- **관리 열**: 상세 버튼(`router.push('/admin/bottle-orders/[id]')`) + "조회 전용" 텍스트. 배송 액션 없음

### /admin/bottle-orders/[orderId] — 주문 상세

보틀 주문 1건의 전체 정보를 읽기 전용으로 표시. 일반상품 주문 상세와 **동일 화면**을 공유한다.

**상단 액션바**:
- "주문 목록으로 돌아가기" → `router.back()` ⚠️ 공용 패턴 — 브라우저 히스토리 기반. 직접 진입 시 이전 페이지가 없을 수 있음
- 주문 상태 배지

**섹션 구성**:
1. **주문 정보** — 주문번호, 주문 ID, 생성 방식(장바구니/단건/관리자수동), 주문 분류, 주문일시, 상품 요약, 라인 수, 총 수량, 가능 액션 목록, 주문 메모
2. **고객 정보** + **결제 정보** (2열 배치)
   - 고객: 이름, 회원 구분, 연락처, 이메일, 사용자 ID, 로그인 ID
   - 결제: 결제수단, 결제상태, 결제 금액, 결제 완료일
3. **상품 라인** — 라인 아이템이 있으면 테이블(상품명/판매공고/상품유형/단가/수량/라인 합계). 없으면 단일 상품 필드
4. **배송 정보** + **금액 요약** (2열 배치)
   - 배송: 수령인, 연락처, 주소, 배송사, 운송장번호, 발송일, 배송완료일, 배송 메모
   - 금액: 상품 합계, 배송비, 할인, 최종 금액, 무료배송 적용 여부(기준/남은 금액)

**상세 페이지 특이사항**:
- 읽기 전용 — 상태 변경/배송 처리 버튼 없음
- `availableAdminActions` 값을 텍스트로만 표시 (실행 불가)
- 잘못된 ID(양수 아님) 또는 404 응답 시 `notFound()` 처리

## 상태 전이 (참고 — 보틀 라우트에서는 관측만)

보틀 라우트는 조회 전용이므로 상태를 바꾸지 않는다. 주문 상태 흐름 참고:

```
결제대기 → 준비중 → 배송중 → 배송완료
취소요청 → 주문취소 / 취소요청 → 취소거절
```

상태 변경 액션(발송/완료/취소 승인·거절)은 일반상품 주문 라우트의 `availableAdminActions` 기반 버튼에서만 가능하다.

## 데이터 흐름

- 모든 페이지 RSC. `getAuthToken()` + `withToken()` 인증.
- 목록: `getApiAdminOrders`에 `productType=BOTTLE` 고정, `sort=createdAt,desc` 최신순
- 상세: `getApiAdminOrdersOrderid` 단건 조회. 404면 `notFound()`
- 필터/페이지네이션은 URL searchParams 기반 — 북마크/공유 가능
- 토큰 리프레시/에러 핸들링은 mutator가 일괄 처리
