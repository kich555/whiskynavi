# 관리자 예약 관리 — `/admin/reservations/*`

위스키 병 예약 공고와 접수 신청을 관리자가 관리. 공고 등록/수정/삭제, 신청 건별 확정·거절·취소, 사업장별 픽업 장소 매핑.

## 라우트 맵

| 경로 | 유형 | 비고 |
|---|---|---|
| `/admin/reservations` | 공고 목록 | |
| `/admin/reservations/new` | 공고 신규 등록 폼 | |
| `/admin/reservations/[noticeId]` | 공고 상세 + 신청 목록 | ★ 이 화면군 핵심 |
| `/admin/reservations/[noticeId]/edit` | 공고 수정 폼 | 수정 불가 상태면 상세로 리다이렉트 |
| `/admin/reservations/business-pickup-location` | 사업장별 픽업 장소 매핑 | 특수 — 별도 설명 |

## 공용 컴포넌트 (admin/_components/)

이 화면군 전반에 쓰이는 공용 UI. 동작 방식 명시.

| 컴포넌트 | 역할 | 동작 |
|---|---|---|
| `AdminHeader` | 상단 헤더(타이틀, 사이드바 토글, 검색) | 사이드바 토글은 context. 검색은 `router.push(현재경로?q=...)` — 페이지 1로 리셋 |
| `Pagination` | URL 기반 페이지네이션 | `router.push(basePath?page=&limit=&...)`. 북마크/공유 가능 |
| `FilterHeader` | 테이블 헤더 내 필터 드롭다운 | `useTableFilter` 기반, URL searchParams 동기화 |
| `NoticeStatusBadge` | 공고 상태 배지 (공용 아님 — reservations 전용) | 읽기 전용 표시 |
| `ReservationExcelDownloadLink` | 엑셀 다운로드 링크 | 공고/배정 현황 엑셀 API 호출 |

**"목록으로 돌아가기" 버튼 패턴**: 상세·폼 페이지 상단. `router.back()` 사용 — 브라우저 히스토리 기반이라 직접 진입 시엔 이전 페이지가 없을 수 있음. 안전한 이동 필요 시 `router.push('/admin/reservations')`로 대체 고려.

## 페이지별 맥락

| ID | 공고명 | 제품명 | 브랜드 | 상태 | 가격 | 신청 수량 | 수락 수량 | 예약기간 | 관리 |
|----|--------|--------|--------|------|------|-----------|-----------|----------|------|
| 12 | 스프링 세일 | 글렌피딕 18 | 글렌피딕 | 진행중 | ₩180,000 | 35병 | 총 50 / 현재 35 / 남은 15 | 2026.03.01 ~ 2026.03.31 | [상세][수정][엑셀] |
| 11 | 겨울 한정판 | 맥콜 12 | 맥콜 | 종료 | ₩95,000 | 50병 | 총 50 / 현재 50 / 남은 0 | 2026.01.01 ~ 2026.01.31 | [상세][엑셀] |

- **행 액션**: 상세(항상), 수정(편집 가능 상태만), 엑셀 다운로드
- **상단 액션**: "보틀예약공고 등록" 버튼 → `router.push('/admin/reservations/new')`
- **검색**: 헤더 검색창 → `q` 파라미터, 페이지 1로 리셋

### /admin/reservations/new — 공고 신규 등록

표준 생성 폼. 병·기간·수량한도·픽업업장·배정방식 입력. 제출 성공 시 상세로 이동.

### /admin/reservations/[noticeId] — 공고 상세 + 신청 목록 ★

공고 1건 정보 + 접수 신청 전체를 한 화면에서 관리. 이 화면군의 핵심.

**상단 액션바**:
- "공고 목록으로 돌아가기" → `router.back()` ⚠️ 공용 패턴
- 엑셀 다운로드
- 편집 → `router.push('/admin/reservations/[id]/edit')` (편집 가능 상태만)
- 삭제 → `deleteNoticeAction` Server Action. **확정/결제 신청 있으면 비활성화**. 성공 시 `router.push('/admin/reservations')` (목록로)

**섹션 구성**:
1. **공고 정보** (`NoticeInfoSection`) — 병, 기간, 가격, 수량 한도
2. **승인 요약** (`ApprovalSummarySection`) — 신청/확정/잔여 수량
3. **배송 정보** (`ReservationDeliverySection`) — 택배 예약 건의 배송회사/송장
4. **신청 목록** (`ApplicationsTableSection`) — 아래 테이블

**신청 목록 테이블** (열 순서):

| ID | 신청 유형 | 신청자 | 연락처 | 신청수량 | 확정수량 | 관리 | 상태 | 픽업 업장 | 내비 커뮤 | 테일즈 커뮤 | 예약신청시각 | 신청 사업장 | 배정 방식 |
|----|-----------|--------|--------|----------|----------|------|------|----------|-----------|-------------|--------------|-------------|------------|
| 301 | 일반 | 홍길동 | 010-1234 | 2 | 2 | [✓][✗][⊘] | 확정 | 강남점 | ● | | 2026.03.05 14:32 | 서울사업장 | 지정 |
| 302 | 사업자 | 김사장 | 010-5678 | 5 | - | [✓][✗] | 신청완료 | 잠실점 | | ● | 2026.03.05 15:01 | 부산사업장 | 랜덤 |

- **건별 액션**(관리 열): 확정✓ / 거절✗ / 취소⊘ — 상태에 따라 활성화. 확정 건은 수량 수정 가능
- **일괄 액션**(테이블 상단, 미처리 신청 있을 때만 활성화):
  - **자동 확정("우선순위최대다수최대행복배정")**: 미처리 신청 전체를 대상으로 자동 배정 로직 실행 — 모달에서 확인 후 일괄 확정
  - **미처리 신청 일괄 거절**: 미처리 신청 건수를 모달에 표시하고 한 번에 전부 거절
- **커뮤니티 배지**(내비/테일즈 커뮤): 멤버십 여부 표시. 수량 한도 차등 표시 목적
- **필터**: 상태·신청 유형·픽업 배정 방식·역할(드롭다운) + 신청/픽업 사업장 ID(직접 입력 폼) — 모두 URL 기반, 새로고침 유지
- **엑셀 내보내기**: 상세 상단 배정 현황 엑셀과 별도로, 신청 목록 테이블 바로 위에 배정 엑셀 내보내기 섹션 존재

**상태 전이**:
`신청완료 → 확정 → 픽업대기 → 수령완료 → 결제완료`
`신청완료 → 거절` / `확정 → 취소`

### /admin/reservations/[noticeId]/edit — 공고 수정

표준 수정 폼. 단, **편집 불가 상태(이미 확정/결제 신청 존재)면 상세로 강제 리다이렉트** — `redirect('/admin/reservations/[id]')` RSC 단에서 처리.

### /admin/reservations/business-pickup-location — 사업장별 픽업 장소 지정 ⚠️ 특수

**목적**: 신청한 사업장이 어느 픽업 업장에서 병을 받을지 기본 매핑 관리. 공고별 오버라이드 전의 전역 세팅.

**특수 동작**:
- **전체 사업장 풀스캔**: 사업자 회원(멤버) 목록을 페이지당 200건, `Promise.all`로 모든 페이지 병렬 페칭 후 사업장 ID 기준 중복 제거해 단일 리스트 구성
- 사업장명 기준 정렬(한글 localeCompare), 이름 동일 시 사업장 ID로 2차 정렬
- 매핑 조회와 사업장 목록 조회를 `Promise.all` 병렬
- 결과: `BusinessPickupSettingContent`에서 사업장↔픽업업장 매핑 UI

일반 CRUD가 아님 — 전역 픽업 매핑 세팅 페이지. 공고 생성 전 세팅, 예외 필요시 공고별 오버라이드.

## 데이터 흐름 (개요)

- 모든 페이지 RSC. `getAuthToken()` + `withToken()` 인증.
- 상세는 `Promise.all`로 공고/신청(등록순 정렬)/배송/배송회사 병렬 페칭. 배송·배송회사는 없을 수 있는 데이터라 조회 실패해도 화면은 정상 렌더(에러 무시 후 undefined 처리). 공고 자체가 없으면 404.
- 변경 액션(확정/거절/취소/생성/수정/삭제)은 Server Action → Orval API.
- 토큰 리프레시/에러 핸들링은 mutator가 일괄 처리.
- 필터/페이지네이션은 URL searchParams 기반 — 북마크/공유 가능.

## 외부 의존

- **인증**: NextAuth (admin 접근 제한)
- **API**: 원격 백엔드 `api.whiskynavi.com` (Orval 코드젠 클라이언트)
- **엑셀**: 상세 페이지 배정 현황 내보내기
- **커뮤니티 역할**: 내비/테일즈 멤버십 API — 수량 한도 차등
