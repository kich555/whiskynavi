# 블라인드 테이스팅 관리자

관리자 메뉴의 **블라인드 관리**에서 진입합니다. 사용자 신청·리뷰 작성 화면은 포함하지 않습니다.

## 운영 순서

1. 리뷰 보틀에서 타사 보틀을 등록하거나 자사 보틀을 이름으로 검색해 가져옵니다. 기존 리뷰 보틀에 판매 보틀을 연결할 수도 있습니다. 새 보틀은 비공개입니다.
2. 샘플을 리뷰 보틀에 연결합니다. 수량은 샘플 마스터가 아닌 공고에서 지정합니다.
3. 회차를 만들고 샘플별 수량과 블라인드 코드를 구성한 후 공고를 게시합니다. 일시는 한국 시간으로 입력·표시하며 API에는 UTC로 전달합니다.
4. 신청 순서와 현재 배분을 확인합니다. 수동 배분 후 1인 목표 총개수를 지정해 선착순 랜덤 배분을 실행하고 모집 마감 후 전체 확정합니다.
5. 신청자를 선택해 배송 준비·송장 등록·배송 조회·수동 완료를 처리합니다. 사고 신고는 별도 메뉴에서 해결하고, 재배송은 이전 배송 ID와 배분 샘플을 지정합니다.
6. 샘플별 리뷰 원문과 작성 현황을 확인합니다. 관리자 메모·태그·중요·검토 여부, 노출·통계 포함 여부를 변경하거나 참여 제한을 부여합니다.
7. 결과·통계를 CSV/XLSX로 추출합니다. 정체 공개는 리뷰 마감 후 제공하며, 결과를 다시 숨겨도 이미 알려진 보틀 정보까지 비공개로 돌아가지는 않습니다.

## 화면

| 경로 | 표시·기능 |
| --- | --- |
| `/admin/blind-tastings` | 회차 상태, 신청 기간, 리뷰 마감, 공개 상태, 회차 생성 |
| `/admin/blind-tastings/bottles` | 이름 검색·페이지 이동, 독립 리뷰 보틀 등록·수정, 자사 가져오기·기존 연결, 비공개 이미지, 카탈로그 공개 |
| `/admin/blind-tastings/samples` | 샘플 이름, 연결 보틀, 관리자 메모, 활성 여부 |
| `/admin/blind-tastings/restrictions` | 회원·신청, 사유, 제한 기간, 상태, 내부 메모, 기간 정정·해제 |
| `/admin/blind-tastings/incidents` | 사고 신고·상태·해결, 재배송 필요 여부 |
| `/admin/blind-tastings/notices/[id]?tab=settings` | 공고·샘플 구성, 게시, 마감 연장, 발송 전 취소 |
| `?tab=applications` | 신청 순서·시각·재신청 횟수, 수동·자동 배분·회수, 확정, 샘플별 잔여 수량 |
| `?tab=shipping&application=…` | 신청별 주소·배송·재배송 이력, 샘플 작성 가능 상태, 수동 완료·면제·정정 |
| `?tab=reviews&sample=…` | 첫 샘플 기본 선택, 원문·닉네임·메모 검색, 제출 시점·숨김 필터, 작성 현황·통계·추출·공개 |
| `?tab=audit` | 처리자·시각·대상·사유·상세 변경 이력 |

표는 컨테이너 전체 너비를 사용하고 작은 화면에서 표 내부만 가로 스크롤합니다. 공통 관리자 메뉴는 768px 미만에서 기본 접힘이며, 열면 본문 위에 표시됩니다. 폼 모달은 화면 높이 안에서 스크롤합니다. 새로고침으로 최신 배분·배송·마감 상태를 불러옵니다.

## 계약·오류 처리

- 각 서버 조회·변경·파일 요청에서 세션과 `ROLE_ADMIN`을 다시 확인합니다. 기존 API 클라이언트의 토큰 갱신 경로를 공유합니다.
- 변경 시 현재 버전을 전송하며, 409 충돌은 최신 상태 조회를 안내합니다. 동일 폼의 통신 실패 재시도에는 같은 중복 방지 키를 유지합니다. 입력을 변경하면 새 키를 만듭니다.
- JSON 리뷰는 재해석·HTML 렌더링 없이 원문 문자열로 표시합니다. 원문 수정·삭제 기능은 없습니다. 관리자 메모와 노출 처리는 별도 필드입니다.
- 다운로드·이미지는 관리자 인증을 확인하는 서버 경유 경로로 전달하며, 비공개 캐시 정책과 바이너리 바이트를 유지합니다.
- 기본 추출은 숨긴 리뷰와 정체 공개 후 제출을 제외하고 회차별 익명 별칭을 사용합니다. 두 포함 옵션과 닉네임 출력은 관리자가 선택합니다.
- 미확정 정책 및 샘플별 리뷰 양식은 백엔드 임시 계약을 그대로 사용합니다. 사용자용 화면·유튜브 제작 기능은 없습니다.

## API 재생성

블라인드 계약은 백엔드 PR #233과 후속 JSON 응답 Content-Type 명시 변경에 의존합니다. 백엔드의 `AdminBlindTastingOpenApiTest`가 생성한 원본을 `openapi/blind-tasting-admin.json`에 보관하고, `pnpm gen:api:blind`로 별도 Orval 클라이언트를 생성합니다. 생성 파일은 직접 수정하지 않습니다.

```bash
# navi-back에서 테스트를 실행한 뒤 navi-front에서 수행
cp ../navi-back/navi-api-admin/build/reports/blind-tasting-openapi.json openapi/blind-tasting-admin.json
pnpm gen:api:blind
```

기존 전체 API 생성 명령 `pnpm gen:api`는 기존 `whiskynavi` 프로젝트를 유지합니다. 백엔드 DDL 적용·API 배포 전에 화면만 배포하면 조회가 실패하므로, 해당 API와 DB를 먼저 준비해야 합니다. 프론트의 새 환경 변수는 없습니다. 기존 `NEXT_PUBLIC_API_BASE_URL`을 사용합니다.

## 검증과 남은 범위

- 서버 액션 인증·배분 계약·한국 시간 변환·필터·중복 키·버전 충돌 테스트.
- 파일 원문 바이트·토큰 갱신·403 거부·파일 라우트의 인증·허용 경로·캐시 테스트.
- 빈 목록, 리뷰 JSON 안전 출력, 발송 후 취소 불가, 충돌 UI, 모바일 메뉴 기본 상태 테스트.
- 격리 예시 데이터로 브라우저에서 모바일 390px·데스크톱 화면, 표 내부 스크롤, 추출 모달·메뉴 동작을 확인했습니다. 예시 화면은 실제 계정·API·DB를 호출하지 않았습니다.
- 실제 관리자 세션과 배포된 블라인드 API를 통한 통합 검증, S3 업로드·CJ 실제 조회는 남아 있습니다.
- 저장소 전체 lint는 기존 파일 및 `repos/effect` 오류로 실패합니다. 변경 범위 lint는 별도로 검증합니다. 전체 `tsc --noEmit`에는 기존 테스트 파일 3건의 타입 오류가 있습니다.
- `graphify` CLI가 설치되지 않아 그래프 갱신은 실행하지 못했습니다. 이 페이지 문서는 직접 갱신했습니다.
