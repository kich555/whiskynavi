# 관리자 사업자 관리 — `/admin/businesses/*`

사업자(업장) 신청 심사와 승인된 업장 정보·권한 관리. 사업자등록증 다운로드, 역할 부여/회수, 업장 정보 인라인 수정, 신청 처리 이력을 한 화면에서 다룬다.

## 라우트 맵

| 경로 | 유형 | 비고 |
|---|---|---|
| `/admin/businesses` | 리다이렉트 | 즉시 `/admin/businesses/applications`로 강제 이동 |
| `/admin/businesses/applications` | 신청 목록 | |
| `/admin/businesses/applications/[applicationId]` | 신청 상세 + 처리 이력 | ★ 승인/반려 액션의 중심 |
| `/admin/businesses/members` | 업장 목록 | 필터/검색/정렬 풍부 — 아래 별도 설명 |
| `/admin/businesses/members/[businessId]` | 업장 상세 + 권한 관리 | ★ 인라인 수정 + 4역할 grant/revoke |

## 공용 컴포넌트 (admin/_components/)

이 화면군 전반에 쓰이는 공용 UI. 동작 방식 명시.

| 컴포넌트 | 역할 | 동작 |
|---|---|---|
| `AdminHeader` | 상단 헤더(타이틀, 사이드바 토글, 검색) | 사이드바 토글은 context. 검색은 `router.push(현재경로?q=...)` — 페이지 1로 리셋. applications는 검색 미사용(`showSearch=false`), members는 검색 필드 선택(사업장명/사용자명) 포함 |
| `Pagination` | URL 기반 페이지네이션 | `router.push(basePath?page=&limit=&...)`. 북마크/공유 가능 |
| `FilterHeader` | 테이블 헤더 내 필터 드롭다운 | `useTableFilter` 기반, URL searchParams 동기화 |

**"목록으로 돌아가기" 버튼 패턴**: 신청 상세·업장 상세 상단. `router.back()` 사용 — 브라우저 히스토리 기반이라 직접 진입 시엔 이전 페이지가 없을 수 있음. 안전한 이동 필요 시 `router.push()`로 대체 고려.

## 페이지별 맥락

### /admin/businesses — 리다이렉트 ⚠️ 특수

RSC 단에서 `redirect("/admin/businesses/applications")` 즉시 강제 이동. 본체 없음 — 사이드바 메뉴("사업자 신청 관리")의 진입점이면서 자동으로 신청 목록으로 보냄.

### /admin/businesses/applications — 신청 목록

**신청 테이블** (행 클릭 = `router.push('/admin/businesses/applications/[id]')`):

| ID | 업체명 | 대표자 | 사업자 구분 | 연락처 | 상태 | 신청일 | 관리 |
|----|--------|--------|------------|--------|------|--------|------|
| 15 | 테스트 주류 | 홍길동 | 가정용 | 010-1234 | 검토중 | 2026.07.15 | [상세] |
| 14 | 부산 주류상사 | 김사장 | 유흥용 | 010-5678 | 승인 | 2026.07.10 | [상세] |

- **사업자 구분**: 가정용(HOUSEHOLD) / 유흥용(ENTERTAINMENT)
- **상태 배지**: 검토중(노랑) / 승인(초록) / 반려(빨강) / 취소(회색)
- **필터**: 상태 드롭다운 — URL 기반, 새로고침 유지
- **행 액션**: 상세 보기 아이콘 (항상)
- **검색**: 미사용

### /admin/businesses/applications/[applicationId] — 신청 상세 + 처리 이력 ★

신청 1건 정보 + 처리 이력을 한 화면에서 관리. 승인/반려 액션의 중심.

**상단 액션바**:
- "신청 목록으로 돌아가기" → `router.back()` ⚠️ 공용 패턴
- **승인/반려 버튼**: PENDING 상태일 때만 노출. 승인/반려 완료 후 버튼 사라짐

**섹션 구성**:
1. **신청 정보** — 신청 ID, 신청자 ID, 신청일, 수정일. 반려 시 반려 사유·관리자 메모 표시
2. **사업자 정보** — 업체명, 사업자등록번호, 사업자 구분, 대표자명, 연락처, 개업일, 과세유형, 픽업 주소. 사업자등록증 다운로드 링크(URL 존재 시)
3. **처리 이력** — auditLogs 존재 시에만 렌더. 상태 전이(이전→이후), 처리 시각, 처리자, 메모

**승인 모달** (overlay-kit):
- 확인 문구만 표시. 승인 성공 시 모달 close + `router.refresh()`
- Server Action이 상세/목록 양쪽 `revalidatePath` 호출

**반려 모달** (overlay-kit):
- **반려 사유(필수)** — 신청자에게 노출
- **내부 메모(선택)** — 신청자에게 미노출
- 반려 사유 공란 제출 시 클라이언트 단 에러("반려 사유를 입력해주세요")
- 성공 시 모달 close + `router.refresh()`

**상태 전이**:
`검토중(PENDING) → 승인(APPROVED)` / `검토중(PENDING) → 반려(REJECTED)`
(사용자 취소: `CANCELED`)

**404 처리**: 존재하지 않는 applicationId 접근 시 API 404 에러를 잡아 `notFound()` 호출.

### /admin/businesses/members — 업장 목록

승인된 사업자(업장) 전체 목록. 필터·검색·정렬이 풍부.

**업장 테이블** (행 클릭 = `router.push('/admin/businesses/members/[businessId]')`):

| 업장ID | 사업자 유형 | 사업장 명 | 사용자명 | 사업자 권한 | 트레일앤테일 | 커뮤니티 | 픽업 | 관리 |
|--------|------------|-----------|----------|------------|-------------|----------|------|------|
| 23 | 가정용 | 강남 주류 | hong@test | 있음 | 없음 | 있음 | 있음 | [상세] |
| 18 | 유흥용 | 부산 주류상사 | kim@test | 있음 | 있음 | 없음 | 없음 | [상세] |

- **검색**: 헤더 검색창 + 검색 필드 선택 드롭다운(사업장명/사용자명). `q` + `searchField` 파라미터, 페이지 1로 리셋
- **정렬**: 최신 등록순(기본) / 오래된 등록순 — `sort` 파라미터, 페이지 1로 리셋
- **필터**(드롭다운, URL 동기화):
  - 사업자 유형: 전체/가정용/유흥용
  - 사업자 권한: 전체/있음/없음
  - 트레일앤테일: 전체/있음/없음
  - 커뮤니티: 전체/있음/없음
  - 픽업: 전체/있음/없음
- **역할 배지**: 4개 역할 각각 있음/없음 배지로 표시 (색상으로 구분: 사업자=보라, 트레일앤테일=파랑, 커뮤니티=초록, 픽업=앰버)

### /admin/businesses/members/[businessId] — 업장 상세 + 권한 관리 ★

업장 1건의 상세 정보 인라인 수정 + 4개 사업자 역할 grant/revoke를 한 화면에서 처리.

**상단 액션바**:
- "업장 목록으로 돌아가기" → `router.back()` ⚠️ 공용 패턴
- 수정 모드 토글: "수정" 버튼 → 인라인 폼 활성화. 저장/취소 버튼으로 전환

**섹션 구성**:
1. **멤버 정보** — User ID, 이름, 이메일 (읽기 전용)
2. **사업자 정보** — 인라인 수정 가능. 4개 하위 섹션:
   - **기본 정보**: 업체명, 사업자등록번호, 사업자 구분(가정용/유흥용 드롭다운), 대표 연락처, 픽업 주소
   - **운영 담당자**: 담당자명, 담당자 전화번호
   - **알림 설정**: 예약 확정/할당 결제 안내 문자(발송/발송 안 함 Switch), 픽업 안내 문자(동일). 기본값 발송
   - **정산 계좌**: 은행명, 예금주명, 계좌번호
   - **문서 및 변경 이력**: 사업자등록증 다운로드(만료 타이머 표시), 사업자 등록일/수정일
3. **권한 정보** — 4개 역할 각각 부여/회수 버튼

**사업자등록증 다운로드 만료 타이머** ⚠️ 특수:
- RSC에서 다운로드 URL 유효 시간을 **9분 30초(570초)**로 계산해 클라이언트에 전달
- 클라이언트는 1초 간격 카운트다운 표시. 0 도달 시 "다운로드 주소가 만료되었습니다." 문구로 전환
- 만료 시각(`documentDownloadExpiresAt`)이 있으면 절대 시각 기준, 없으면 초기 남은 초 기준 단순 감산

**권한 grant/revoke** ⚠️ 특수:
- 4개 역할: 사업자(`ROLE_BUSINESS`), 트레일앤테일(`ROLE_TRAILNTALE_BUSINESS`), 커뮤니티(`ROLE_COMMUNITY_BUSINESS`), 픽업(`ROLE_PICK_UP_BUSINESS`)
- 각 역할마다 부여/회수 버튼 쌍. 현재 보유 상태에 따라 한쪽 비활성화:
  - 보유 중 → 부여 버튼 비활성화, 회수 버튼 활성화
  - 미보유 → 부여 버튼 활성화, 회수 버튼 비활성화
  - **어느 한 역할 처리 진행 중이면 다른 모든 버튼 비활성화** (직렬 처리 강제)
- Server Action 호출 후 `router.refresh()`. 성공/실패 메시지 인라인 표시
- 픽업 권한은 별도 확인 모달(overlay-kit) 거쳐 처리. 나머지 3개 역할은 버튼 직접 호출 (모달 없음)

**404 처리**: 존재하지 않는 businessId 접근 시 API 404 에러를 잡아 `notFound()` 호출.

## 데이터 흐름 (개요)

- 모든 페이지 RSC. `getAuthToken()` + `withToken()` 인증.
- 신청 상세는 `Promise.all`로 신청 정보/처리 이력 병렬 페칭.
- 업장 상세는 단일 API 호출 후 클라이언트에 만료 시각 계산값 전달.
- 변경 액션(승인/반려/역할 grant·revoke/업장 정보 수정)은 Server Action → Orval API. 성공 시 `revalidatePath`로 상세/목록 양쪽 갱신 + `router.refresh()`.
- 토큰 리프레시/에러 핸들링은 mutator가 일괄 처리.
- 필터/페이지네이션/정렬/검색은 URL searchParams 기반 — 북마크/공유 가능.

## 외부 의존

- **인증**: NextAuth (admin 접근 제한)
- **API**: 원격 백엔드 `api.whiskynavi.com` (Orval 코드젠 클라이언트)
- **사업자등록증**: 사업자등록증 파일 다운로드 URL — 시간 제한 있음 (9분 30초)
- **사업자 역할**: 4종(사업자/트레일앤테일/커뮤니티/픽업) — 멤버십·커뮤니티 기능과 픽업 권한 연관
