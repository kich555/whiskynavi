# 관리자 1:1 문의 관리 — `/admin/inquiries/*`

사용자가 남긴 1:1 문의를 관리자가 확인·답변·종료/재오픈하는 대화형 문의 화면군. 단순 CRUD가 아닌 **메시지 스레드 기반 문의 채널**이 핵심.

## 라우트 맵

| 경로 | 유형 | 비고 |
|---|---|---|
| `/admin/inquiries` | 문의 목록 | 최근 메시지 시각 역순 고정 정렬 |
| `/admin/inquiries/[inquiryId]` | 문의 상세 + 메시지 스레드 + 답변 폼 | ★ 이 화면군 핵심 |

## 공용 컴포넌트 (admin/_components/)

이 화면군 전반에 쓰이는 공용 UI. 동작 방식 명시.

| 컴포넌트 | 역할 | 동작 |
|---|---|---|
| `AdminHeader` | 상단 헤더(타이틀, 사이드바 토글) | 사이드바 토글은 context. 이 화면군에서는 검색 비활성화(`showSearch=false`) |
| `Pagination` | URL 기반 페이지네이션 | `router.push(basePath?page=&limit=&...)`. 북마크/공유 가능 |

**"문의 목록으로" 버튼 패턴**: 상세 페이지 상단. reservations의 `router.back()` 패턴과 달리 **`router.push('/admin/inquiries')` 사용** — 직접 진입 히스토리가 없어도 항상 목록으로 안전하게 이동. (행 클릭으로 들어온 경우에도 히스토리 의존 없이 일관된 동작)

## 페이지별 맥락

### /admin/inquiries — 문의 목록

**문의 테이블** (행 클릭 = `router.push('/admin/inquiries/[id]')`):

| ID | 사용자 | 제목 | 상태 | 최근 메시지 | 관리 |
|----|--------|------|------|-------------|------|
| 87 | #1024 | 배송 언제 오나요 | 답변 대기 | 2026.08.01 14:32 | [👁] |
| 86 | #0917 | 쿠폰 적용 문의 | 답변 완료 | 2026.07.30 09:15 | [👁] |

- **정렬**: `lastMessageAt,desc` 고정 — 최근 활동 문의가 최상단. 사용자 변경 불가
- **상태 배지**: 답변 대기(amber) / 답변 완료(emerald) / 문의 종료(gray)
- **상태 필터**: 우측 셀렉트 드롭다운(전체/답변대기/답변완료/문의종료). 변경 시 `status` 파라미터 + **페이지 1 리셋**
- **행 액션**: 상세 보기(눈 아이콘, 행 클릭과 동일 이동) — 생성/수정/삭제 액션 없음
- **검색 비활성화**: 헤더 검색창 미사용. 오직 상태 필터 + 페이지네이션만 URL 동기화
- **빈 상태**: 해당 상태 문의 없음 안내

### /admin/inquiries/[inquiryId] — 문의 상세 + 메시지 스레드 ★

문의 1건의 전체 대화를 보며 관리자가 답변을 달고 종료/재오픈하는 핵심 화면. 단순 상세 조회가 아니라 **대화형 답변 채널**.

**상단 액션바**:
- "문의 목록으로" → `router.push('/admin/inquiries')` ⚠️ 공용 패턴 변형 (`back` 아님)
- 상태 토글 버튼: 종료(`close`) / 다시 열기(`reopen`) — 현재 상태에 따라 라벨·아이콘 전환

**헤더 섹션**:
- 상태 배지 + 문의 ID
- 문의 제목
- 작성자 링크(`/admin/users/[userId]`로 이동, ExternalLink 아이콘) · 등록 시각 · 최근 메시지 시각

**메시지 스레드**:
- 전체 메시지를 채팅 형태로 렌더 (사용자=좌측 회색 말풍선 / 관리자=우측 amber 말풍선)
- 작성자 표시: 이름(닉네임) 우선, 없으면 `관리자 #id` / `사용자 #id` 폴백
- 메시지 내용은 리치텍스트(HTML sanitize 후 렌더)
- 메시지별 시각 표시

**관리자 답변 폼** (하단):
- 리치텍스트 + 이미지 업로드 에디터
- **이미지 업로드**: 클라이언트에서 `getSession()`으로 토큰 직접 획득 → boards 업로드 API 호출. 업로드 중에는 제출 버튼 비활성화
- 제출 → `replyInquiryAction` Server Action. 성공 시 폼 리셋 + `router.refresh()` (메시지 목록 갱신)
- 빈 내용/이미지만 있는 경우 Zod 검증 + 리치텍스트 내용 검증으로 차단

**상태 전이 / 비활성화 조건**:
- `WAITING → ANSWERED`: 답변 등록 시 백엔드에서 자동 전이 (UI가 직접 변경하지 않음)
- `ANSWERED ⇄ CLOSED`: 관리자가 종료/재오픈 버튼으로 토글. `useTransition`으로 pending 중 중복 클릭 방지
- **답변 폼 비활성화**: 문의가 `CLOSED` 상태면 폼 대신 "종료된 문의입니다. 답변하려면 문의를 다시 열어주세요." 안내 표시 → 재오픈해야 답변 가능

**404 처리**: ID가 양수가 아니거나, API가 404를 반환하거나, 문의 데이터가 없으면 `notFound()`. 잘못된 직접 진입 보호.

## 데이터 흐름 (개요)

- 모든 페이지 RSC. `getAuthToken()` + `withToken()` 인증.
- 목록은 검색 파라미터(page, limit, status) 기반 페칭 — 북마크/공유 가능.
- 상세는 단일 문의 + 메시지 배열을 RSC에서 페칭 후 클라이언트 컴포넌트로 전달.
- 답변/종료/재오픈은 Server Action → Orval API. 성공 시 `revalidatePath`로 목록·상세 캐시 갱신 + `router.refresh()`.
- 토큰 리프레시/에러 핸들링은 mutator가 일괄 처리. 단, **이미지 업로드만 클라이언트에서 `getSession()` 직접 호출** — RSC 컨텍스트 밖이라 토큰을 별도 획득.

## 외부 의존

- **인증**: NextAuth (admin 접근 제한). 이미지 업로드는 클라이언트 세션 토큰 사용
- **API**: 원격 백엔드 `api.whiskynavi.com` (Orval 코드젠 클라이언트) — 문의 목록/상세/답변/종료/재오픈
- **리치텍스트**: `sanitizeRichTextContent`로 메시지 HTML 정제, `RichTextImageEditor`로 답변 작성
- **사용자 관리 연동**: 상세에서 작성자 링크 → `/admin/users/[userId]`
