# 이용권 관리 — `/admin/service-entitlements`

일반상품 메뉴의 **이용권 관리**에서 주문을 먼저 열지 않고 전체 발급 이용권을 조회하고 개별 사용 완료 처리한다. 관리자 인증이 필요하며 목록 조회와 사용 요청 모두 서버에서도 관리자 권한을 검사한다.

## 검색과 목록

- 상품명, 외부 주문번호, 구매자 이름, 연락처의 부분 문자열 검색. 이용권 번호와 주문 ID는 정확한 번호로 조회한다. 여러 조건은 함께 적용한다.
- 이용 가능 / 이용 시작 전 / 만료 / 사용 완료 / 취소 / 이용 정지 필터. 상태는 조회 시점의 주문·결제와 이용 기간을 반영한다.
- 최신 발급 번호 순으로 최대 50건씩 표시한다. 다음 50건은 검색 조건을 유지하며, 처음 목록으로 돌아갈 수 있다. 검색을 다시 하면 첫 목록부터 조회한다.
- 구매자 이름·연락처, 회원/비회원 구분, 이용권·주문번호, 이용 기간과 발급 시각을 표시한다. 주문번호로 기존 일반상품 주문 상세를 연다.
- 사용 기록을 펼치면 실제 처리 시각·처리자 ID·확인 사유를 확인한다. 비회원 본인 처리는 처리자 ID 없이 표시한다. 취소된 이용권에도 과거 사용 기록은 유지한다.
- 조회 실패는 빈 목록과 구분해서 안내한다. 인증 만료·권한 부족·잘못된 검색값·서버 오류를 표시하며 새로고침으로 다시 조회한다.

## 사용 완료

이용 가능·시작 전·만료 이용권은 사유를 필수 입력해 사용 완료 처리한다. 관리자는 기간 제한만 예외이며 미결제·취소 진행·취소·중복 사용은 서버가 거부한다. 실제 이용 확인 후 처리하고 되돌리기는 제공하지 않는다. 사용 후 주문 전체 취소가 제한됨을 안내한다.

처리 중에는 해당 입력과 버튼을 잠그고, 성공하면 해당 처리 폼을 숨기고 목록을 다시 조회한다. 최신 상태와 충돌하거나 네트워크 오류가 나도 결과 안내와 함께 재조회한다. 기존 주문 상세와 동일한 사용 폼과 API를 사용한다. 일괄 사용·사용 취소·유효기간 변경 기능은 포함하지 않는다.

## 연결

상단에서 일반상품 판매공고 등록과 이용권 주문 목록으로 이동한다. 이용권 판매공고는 기존 등록 화면에서 전달 방식을 티켓·무형서비스로 선택한다.

별도 DB 변경이나 환경 변수는 없다. 백엔드의 관리자 전체 이용권 조회 API를 먼저 반영한 뒤 프론트를 배포한다. 기존 이용권 기능의 미적용 마이그레이션은 먼저 적용해야 한다.
