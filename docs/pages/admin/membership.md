# 관리자 멤버십 관리 — `/admin/membership/*`

두 커뮤니티 브랜드(위스키내비 · 더 위스키테일즈)의 멤버십 회원을 관리자가 추가/해제하고, 브랜드별 멤버십 혜택을 조회·편집한다. 멤버십은 사용자 역할(`ROLE_WHISKYNAVI_MEMBER` / `ROLE_WHISKYTALES_MEMBER`)의 부착·제거로 구현되며, 이 역할 여부가 예약 수량 한도 차등 등 도메인 전반에 영향을 준다.

## 라우트 맵

| 경로 | 유형 | 비고 |
|---|---|---|
| `/admin/membership` | 멤버십 회원 목록 | ★ 이 화면군 핵심 |
| `/admin/membership/benefits` | 브랜드별 멤버십 혜택 조회/편집 | 혜택 API 미연결 — 현재 로컬 상태 only |

## 도메인 배경

- **두 브랜드**: `navi`(위스키내비) / `tales`(더 위스키테일즈). 전 페이지에 걸쳐 이진 선택 탭/버튼으로 전환.
- **멤버십 = 역할 부착**: 브랜드 선택이 곧 부착/해제할 역할을 결정. 사용자는 두 브랜드 멤버십을 동시에 보유할 수 있다(목록 테이블의 멤버십 열에 배지가 여러 개 표시될 수 있음).
- **회원 유형 파생**: 사용자의 역할 목록에 사업장 계열 역할이 하나라도 있으면 "업장", 아니면 "일반"으로 표시. 멤버십 역할과는 독립적.
- **커뮤니티 영향**: 멤버십 역할 보유 여부는 예약 공고의 수량 한도 차등(내비/테일즈 커뮤 배지)으로 이어짐 — `/admin/reservations` 신청 목록의 커뮤 배지와 동일 역할 기준.

## 공용 컴포넌트 (admin/_components/)

이 화면군 전반에 쓰이는 공용 UI. 동작 방식 명시.

| 컴포넌트 | 역할 | 동작 |
|---|---|---|
| `AdminHeader` | 상단 헤더(타이틀, 사이드바 토글) | 사이드바 토글은 context. **검색 비활성화**(`showSearch={false}`) — 이 화면군은 헤더 검색 대신 페이지 내 전용 UI 사용 |
| `Pagination` | URL 기반 페이지네이션 | `router.push(basePath?page=&limit=&...)`. 북마크/공유 가능 |

**"돌아가기" 버튼 패턴**: 혜택 관리 페이지 상단의 "멤버십 관리로 돌아가기"는 `router.back()` 사용 — 브라우저 히스토리 기반이라 직접 진입 시엔 이전 페이지가 없을 수 있음. 안전한 이동 필요 시 `router.push('/admin/membership')`로 대체 고려.

## 페이지별 맥락

### /admin/membership — 멤버십 회원 목록 ★

현재 선택된 브랜드의 멤버십 회원 전체를 표 페이징 조회. 브랜드 전환, 정렬, 추가/해제를 한 화면에서.

**상단 액션바**:
- **브랜드 탭**(위스키내비 / 더 위스키테일즈) — 전환 시 `brand` 파라미터 변경 + **페이지 1로 리셋**. 활성 탭이 amber-600 하이라이트.
- **"혜택 관리" 버튼** → `router.push('/admin/membership/benefits')`
- **"멤버십 추가" 버튼** → 추가 모달 오픈 (`overlay.open`)

**정렬/요약 행**:
- 정렬 기준 셀렉트: 가입일(`createdAt`, 기본) / 이름(`name`). 변경 시 **페이지 1로 리셋**.
- 정렬 방향 토글 버튼: 오름차순↑ / 내림차순↓ (기본 desc). 변경 시 **페이지 유지**.
- 우측 요약: "총 N명의 멤버"

**멤버십 회원 테이블** (행 = 현재 브랜드 멤버십 보유 사용자):

| ID | 이름 | 닉네임 | 전화번호 | 회원유형 | 멤버십 | 가입일 | 관리 |
|----|------|--------|----------|----------|--------|--------|------|
| 42 | 홍길동 | @hong | 010-1234-5678 | 일반 | 내비 | 2026.07.15 | [해제] |
| 57 | 김사장 | @boss | - | 업장 | 내비 테일즈 | 2026.06.30 | [해제] |

- **회원유형**: 사업장 계열 역할 있으면 "업장"(보라), 없으면 "일반"(회색) — 멤버십과 무관한 파생 표시.
- **멤버십 배지**: 보유한 멤버십 역할 전체 표시. 내비=amber, 테일즈=blue. 두 브랜드 동시 보유 시 배지 2개.
- **관리 열**: "멤버십 해제" 버튼(회색 → 호버 red). 클릭 시 해제 확인 모달 오픈.
- **빈 상태**: "멤버십 회원이 없습니다." 행. 로딩 중엔 skeleton 5행.

**멤버십 추가 모달**:
1. 브랜드 선택(진입 시 현재 브랜드가 기본값, 모달 내에서 재선택 가능)
2. 사용자 검색 인풋 — blacklist 화면과 공용인 `UserSearchInput`. 이름 입력 → 드롭다운 결과에서 사용자 선택. 선택 시 이름/이메일/닉네임 요약 카드 표시.
3. "멤버십 추가" 버튼 — 사용자 미선택 또는 진행 중이면 **비활성화**. 성공 시 모달 닫고 `router.refresh()`로 목록 갱신. 실패 시 모달 내 에러 메시지.

**멤버십 해제 확인 모달**:
- "정말로 해제하시겠습니까?" 경고(빨간 강조). "해제된 멤버십은 다시 추가할 수 있습니다." 안내.
- 확인 시 Server Action 호출 → 실패면 `toast.error`. 성공 시 `router.refresh()`.

### /admin/membership/benefits — 브랜드별 멤버십 혜택 관리 ⚠️ 혜택 API 미연결

**목적**: 두 브랜드 각각의 멤버 혜택(할인율, 조기 접근 일수, 무료 배송/독점 제품/우선 지원 on-off)을 카드 형태로 조회·편집.

**현재 상태 — 로컬 전용**:
- 페이지는 RSC이나 서버 페칭 없이 클라이언트 컴포넌트만 렌더. 초기 데이터는 하드코드된 기본값(할인 10%, 조기 접근 2일, 나머지 on).
- 편집 모드 진입 → 로컬 state 복사본 수정 → 저장 시 로컬 state 갱신 **만** 수행. **서버 저장 API 호출 없음** (`TODO`로 표기됨).
- 즉 새로고침하면 편집 내용이 사라짐. API 연결 전까지는 뷰/입력 폼 프로토타입.

**뷰 모드**(기본):
- "멤버십 관리로 돌아가기" → `router.back()` ⚠️ 공용 패턴
- 우측 "편집" 버튼
- 두 브랜드 카드(NAVI 회원 / TALES 회원) 나란히 표시 — 각 혜택 항목별 값/체크 표시(녹색 ✓ / 회색 ✗)

**편집 모드**:
- "저장"/"취소" 버튼으로 전환. 저장은 로컬 state만 갱신(위 참고).
- 할인율(%), 조기 접근(일) — number 인풋. 나머지 3종 — Switch 토글.
- "취소" 시 편집 전 값으로 롤백.

## 상태 전이 / 예외 로직

- **브랜드 전환·정렬 기준 변경**: 페이지 1로 강제 리셋. 정렬 방향 토글만 페이지 유지.
- **비활성화 조건**: 추가 모달의 "멤버십 추가" 버튼 — 사용자 미선택 또는 `isPending` 시 비활성화.
- **강제 리다이렉트**: 없음. 브랜드 파라미터가 누락/무효(`tales` 외 값)면 RSC 단에서 `navi`로 정규화.
- **멤버십 해제 후 재추가 가능** — 모달 안내문대로 영구 삭제 아님. 역할 remove/add API로 구현.

## 데이터 흐름 (개요)

- 목록 페이지는 RSC. `getAuthToken()` + `withToken()` 인증 후, 선택 브랜드에 해당하는 역할로 사용자 목록 API 호출. `brand` 파라미터가 조회 역할을 결정.
- 추가/해제는 Server Action → 역할 add/remove PATCH API. Zod로 `userId`/`brand` 검증. 성공 시 `revalidatePath('/admin/membership')` + 클라이언트 `router.refresh()`.
- 혜택 페이지는 API 미연결 — 서버 페칭/액션 없음.
- 토큰 리프레시/에러 핸들링은 mutator가 일괄 처리.
- 필터/페이지네이션/정렬은 URL searchParams 기반 — 북마크/공유 가능.

## 외부 의존

- **인증**: NextAuth (admin 접근 제한)
- **API**: 원격 백엔드 `api.whiskynavi.com` (Orval 코드젠 클라이언트) — 역할 add/remove 엔드포인트. 혜택 API는 미구현.
- **사용자 검색**: blacklist 화면의 `UserSearchInput` 재사용 — `useUserSearch` 훅 기반 이름 검색.
- **커뮤니티 역할**: 내비/테일즈 멤버십 역할 — 예약 수량 한도 차등 등 도메인 전반에 영향.
