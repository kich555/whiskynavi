# 사업자 픽업 관리 — `/business/*`

픽업 예약 사업장 계정(ROLE_BUSINESS)이 자신의 공고·신청·매니저를 관리하는 사업자 화면. 관리자(`admin`)가 전체 사업장을 통할 때와 달리, 로그인한 사업자 본인의 사업장 범위만 노출된다. 사이드바의 사업장 전환기로 복수 사업장을 오가며 동일한 통계/관리 뷰를 본다.

## 라우트 맵

| 경로 | 유형 | 비고 |
|---|---|---|
| `/business` | 홈(진입점) | ★ 특수 — `/business/statistics`로 강제 리다이렉트. 자체 화면 없음 |
| `/business/statistics` | 공고별 예약 통계 | 사업장 진입 후 기본 도착지. 이 화면군의 메인 대시보드 |
| `/business/members` | 사업장 멤버 관리 | 소유자/매니저 목록, 매니저 추가·삭제, 소유권 이전 |

> `/business/pickup-reservations/*`는 별도 공고 관리 화면군. 이 문서 범위 밖.

## 접근 제어 (레이아웃 단)

`/business/*` 전역 레이아웃이 모든 하위 페이지 앞에서 게이트 역할. 세 단계 검사:

1. **미인증** (session 없음) → `redirect("/sign-in")` 강제 리다이렉트
2. **ROLE_BUSINESS 없음** → `BusinessUnauthorizedPage` 렌더 (리다이렉트 아님). "메인 페이지로 돌아가기" 버튼 → `router.push("/")`
3. **통과** → 사이드바 + 자식 페이지 렌더. 사업장 컨텍스트를 병렬로 페칭해 사이드바에 전달

## 공용 컴포넌트 (`business/_components/`)

사업자 화면 전반에 쓰이는 공용 UI. 동작 방식 명시.

| 컴포넌트 | 역할 | 동작 |
|---|---|---|
| `BusinessSidebar` | 좌측 사이드바. 사업장 선택기 + 네비 메뉴 + 일반 페이지 복귀 | 사업장 선택은 `router.push(현재경로?businessId=...)` — `page` 파라미터 제거 후 URL 동기화. "대표로 지정"은 Server Action 후 `router.refresh()`. "일반 페이지로 돌아가기"는 `<Link href="/">` |
| `BusinessHeader` | 각 페이지 상단 고정 타이틀 바 | 정적 표시. 라우터 동작 없음 |
| `BusinessUnauthorizedPage` | 권한 없음 안내 | "메인 페이지로 돌아가기" → `router.push("/")` |

**사업장 전환 동작**: 사이드바에서 사업장을 바꾸면 `businessId` searchParam 갱신 + `page` 리셋. 선택은 URL 기반이라 북마크/공유 가능. 대표 사업장 지정은 OWNER 권한일 때만 버튼 노출.

**"일반 페이지로 돌아가기" 패턴**: 사이드바 하단. `<Link href="/">` push 기반 — 사업자 모드를 빠져나와 일반 사용자 홈으로 이동. `router.back()`이 아니므로 히스토리 무관.

## 페이지별 맥락

### /business — 홈 (강제 리다이렉트) ⚠️ 특수

**목적**: `/business` 직접 진입 또는 사이드바 "픽업 사업장" 로고 클릭 시의 안전한 도착점. 자체 화면을 렌더하지 않고 RSC 단에서 즉시 `redirect("/business/statistics")`. 별도 로딩/빈 상태 없이 통계 페이지로 곧장 보낸다.

일반적인 인덱스 페이지가 아님 — 사업장 진입 후 곧장 통계 대시보드를 보여주기 위한 라우팅 처리.

### /business/statistics — 공고별 예약 통계 ★ 메인

사업장의 픽업 예약 공고들을 단계별 승인 현황과 함께 카드 목록으로 보여주는 대시보드. 이 화면군의 기본 도착지(` /business` 리다이렉트 목적지).

**공고 통계 카드** (공고당 1개):

| 공고명 | 제품명 | 공고 ID | 승인 | 결제완료 | 픽업대기 | 수령완료 | 액션 |
|--------|--------|---------|------|----------|----------|----------|------|
| 스프링 세일 | 글렌피딕 18 | #12 | 35병 (100%) | 20병 (57%) | 10병 (29%) | 5병 (14%) | [공고 내용][신청 관리] |
| 겨울 한정판 | 맥콜 12 | #11 | 50병 (100%) | 50병 (100%) | 50병 (100%) | 48병 (96%) | [공고 내용][신청 관리] |

- **단계 진행률**: 승인 수량을 기준(100%)으로 삼고, 결제완료·픽업대기·수령완료를 승인 대비 비율로 원형 게이지(conic-gradient)로 표시. 승인 자체는 항상 100%
- **공고명 표시**: 공고명 우선, 없으면 제품명, 둘 다 없으면 "이름 없는 예약 공고". 부가 제품명은 공고명과 다를 때만 표시
- **카드 액션**:
  - "공고 내용" → `/business/pickup-reservations/notices/[noticeId]/detail` (읽기 전용 상세)
  - "신청 관리" → `/business/pickup-reservations/notices/[noticeId]` (신청 건 관리)
  - noticeId 없는 공고는 "상세" 버튼 비활성화
- **사업장 필터**: `businessId` searchParam. 사이드바 선택값과 동기화. 미지정 시 백엔드 기본 사업장
- **페이지네이션**: 공고 5건/page. URL 기반(`page` 파라미터). 총 공고 수가 5 이하면 카운트만 표시하고 페이지 버튼 숨김. `businessId`를 페이지 링크에 유지

**빈 상태**: 통계가 없으면 "표시할 공고별 예약 통계가 없습니다." 안내.

### /business/members — 사업장 멤버 관리

현재 선택된 사업장의 소유자와 매니저 목록을 관리. 매니저 추가/삭제와 소유권 이전.

**상단 요약**: 현재 기본 사업장명·주소·내 역할 배지(소유자/매니저).

**권한 분기**: 현재 사용자의 역할이 `OWNER`인지에 따라 UI가 크게 갈린다.
- **OWNER**: 매니저 추가 폼 + 멤버 테이블의 관리 버튼 활성화
- **MANAGER**: "사업장 소유자만 멤버를 변경할 수 있습니다." 안내. 추가 폼 숨김, 관리 버튼 없음 (읽기 전용)

**매니저 추가 폼** (OWNER만): 이메일 입력 → "매니저 추가". 성공 시 `router.refresh()`로 목록 갱신.

**멤버 테이블**:

| 사용자 | 이메일 | 권한 | 관리 |
|--------|--------|------|------|
| 홍길동 / ID 101 | hong@example.com | 매니저 | [소유권 이전][삭제] |
| 김사장 / ID 1 | owner@example.com | 소유자 | - |

- **관리 액션**(OWNER만, 본인 소유자 행 제외):
  - "소유권 이전" → `window.confirm("이 사용자에게 사업장 소유권을 이전하시겠습니까?")` 확인 후 Server Action. 성공 시 `router.refresh()`
  - "삭제" → 매니저 제거. 즉시 실행(confirm 없음)
- **소유자 행**: 관리 버튼 없이 "-" 표시. 본인이 소유자라도 다른 소유자 행을 편집할 수 없음(소유자는 1명)
- **빈 상태**: 사업장 멤버가 없으면 안내문. 사업장 자체가 없으면 "연결된 사업장이 없습니다."

## 상태 전이 / 예외 로직

- **미인증 → `/sign-in` 강제 리다이렉트** (레이아웃 RSC 단)
- **ROLE_BUSINESS 없음 → 권한 없음 페이지** (리다이렉트 아닌 인플레이스 안내)
- **`/business` → `/business/statistics` 강제 리다이렉트** (홈 진입 시 곧장 통계로)
- **OWNER 전용 관리**: 멤버 추가/삭제/소유권 이전은 OWNER 역할일 때만 노출. MANAGER는 읽기 전용
- **소유권 이전 confirm**: 브라우저 `window.confirm`으로 사전 확인. 유일하게 confirm이 붙는 액션 (매니저 추가/삭제는 즉시 실행)
- **대표 사업장 지정**: OWNER만 가능. Server Action 후 `router.refresh()` (URL 변경 아닌 서버 캐시 갱신)

## 데이터 흐름 (개요)

- 모든 페이지 RSC. `getAuthToken()` + `withToken()` 인증.
- 레이아웃이 사업장 컨텍스트(`businesses`, 현재 사업장, 멤버)를 1회 페칭. members 페이지는 동일 컨텍스트 엔드포인트 재사용.
- statistics 페이지는 별도 통계 API 호출 (공고 단계별 집계, 페이지 5건).
- 변경 액션(매니저 추가/삭제/소유권 이전/대표 지정)은 Server Action → Orval API → 성공 시 관련 경로 일괄 `revalidatePath`.
- 사업장 전환은 URL searchParam 기반 — 페이지 재페칭은 RSC 라우터가 처리.

## 외부 의존

- **인증**: NextAuth. `ROLE_BUSINESS` 역할 보유자만 접근. 비소유자는 권한 없음 페이지.
- **API**: 원격 백엔드 `api.whiskynavi.com` (Orval 코드젠 클라이언트). 사업장 컨텍스트, 통계, 멤버 관리 엔드포인트.
- **사업장 컨텍스트**: 1개 엔드포인트에서 사업장 목록 + 현재 사업장 + 멤버를 한 번에 제공. 레이아웃과 members 페이지가 공유.
